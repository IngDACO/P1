# Lift Installation — Stage → Activity → Task (DRAFT v3 — with weights)

Status: draft for joint review. Weights below are my logical first-pass estimates based on typical relative time/effort/complexity — NOT field-verified yet. Expect us to adjust these together once you apply your 7 years of experience and cross-check against real logs.

Progress model: additive/order-independent.
- Each Stage has a weight = its share of the overall 100% installation.
- Within each Stage, each Activity has a weight = its share of that Stage's 100%.
- An activity's contribution to OVERALL progress = (Stage weight) x (Activity % within stage).
  Example: Stage 6 "Shaft Climb & Bedplates" = 15% of the job. "Install motor bedplate" = 20% of that stage. So finishing that one activity = 15% x 20% = 3.0% of total job progress.

This document represents the IDEAL sequence — real installs jump around. The structure is a measuring tool: a fixed, weighted menu of everything that *can* be logged, so freeform daily entries can be interpreted and mapped to progress regardless of actual order.

## MECHANICAL INSTALLATION

### Stage 1 — Set Up (3% of total)
| Activity | % of stage |
|---|---|
| Receive toolbox | 6% |
| Receive Inex kit | 9% |
| Receive lift delivery | 12% |
| Count/verify all boxes against delivery manifest | 12% |
| Check box codes (multi-lift sites) | 8% |
| Paperwork (hand-over/procedure forms, SWMS sign-off, etc.) | 12% |
| Snap test (trimmer beam/hook point load test) | 8% |
| Builders lift protection & handover (conditional, job-specific) | 6% |
| Hang temporary work lighting | 4% |
| Compound/Hoardings (transport, building, protection, etc.) | 8% |
| Install sky climber (conditional — only on jobs using a false car) | 9% |
| Install sky lock (conditional — only on jobs using a false car) | 6% |

Note (Danilo, Sep 2026): **Sky climber and sky lock confirmed as their own weighted activities here in Stage 1**, not a flagged/unscored side-system. Sky climber = the false car's motor equivalent — needs a rope installed, needs its own power, and has a pendant (control). Sky lock = the false car's speed governor equivalent — simpler, just needs the rope installed, and attaches directly to the safety gear; it triggers the same way any speed governor does. Both conditional — only on jobs that use a false car instead of/alongside a tirak. Weights above are rebalanced against the existing Stage 1 placeholders per the usual "temporary estimate" caveat.

Note (Danilo, Aug 2026): the snap test isn't rip-out-exclusive. It's supposed to happen at the very beginning of any job — performing it mid-job (as seen in one log) is a mistake and a safety risk, since the beam should be verified before it's relied on. Full new installs (no rip-out) also need their own snap test, so it belongs here in Stage 1 as well as in Rip-Out R1. Also called a "pull test."

Note (Danilo, Aug 2026): a **builders lift** is a temporary lift the builder uses in place of their construction hoist, ahead of final handover to the client. Requires its own protection — interior (floor, walls, ceiling) and every landing door frame — kept in good condition through construction use. Conditional, not every job has one.

Notes (Danilo, Aug 2026):
- **Cabin doors** are distinct from the cabin walls/"reverses" (the front walls forming the door opening) — the doors themselves are a separate task, alongside the cabin header.
- **Uprights** are two structural frame members that are part of the cabin assembly (confirmed as Car Assembly, not a separate "superstructure" stage), joined together at the top by the **top bow**. "Roof" in this context is just the cabin ceiling — same task as "Install cabin ceiling," not a distinct component.
- **Omega bracket = combination bracket = "combo bracket"** — same component, alternate names.
- **Stopblock is a temporary device, not a permanent one.** (Earlier draft implied it was a permanent platform-mounted governor — corrected.) It's attached early alongside the tirak and stays in place through the shaft climb; it's removed later, alongside tirak removal (Stage 13, Belting & Finishes — see "Remove stopblock" there), not at rails-reach-top as an earlier draft assumed — same device across its install/removal lifecycle, not two different components.
- **Speed governor is one system spanning three locations:** the governor device itself sits at the top on the single/Z-side bedplate (Stage 6), its rope runs down to a tensioner device (the "Jenny wheel") pinned to the rail in the pit (Stage 8), and the same rope gets attached to the cabin (here). A log saying "speed governor on cabin" refers to this rope attachment, not a second governor device.
- **Safety gripper gets a quick initial calibration here**, as an exception to the general "tune verb → Stage 14" rule — this happens right after the cabin is first installed. It's recalibrated properly later during full commissioning tuning (Stage 14), so the same component can legitimately show up as "tuned" at both points in a job.
- **Cabin toe guard confirmed as its own real, weighted activity here** (Danilo, Sep 2026) — mounted under the cabin sill. Distinct physical component from the landing toe guards/skirts in Stage 7 (Landing Doors); same name, different piece — check context for which one a log entry means.
- **Earth cabin platform confirmed as its own real, weighted activity here** (Danilo, Sep 2026) — earthing the cabin platform itself, part of Car Assembly. A log entry that reads like someone double-checking whether the platform earthing was already done maps to this task, not to rework.

# RIP-OUT (separate 100% track)

This is a distinct project phase with its own independent 100% — NOT part of the installation 100% above, and not summed with it. A job with rip-out + install effectively has two separate progress trackers running (Rip-Out 0-100%, then Installation 0-100%).

## RIP-OUT STAGE WEIGHTS (sum = 100%)

| # | Stage | Weight |
|---|-------|--------|
| R0 | Set Up | 10% |
| R1 | Take Possession & Initial Shutdown | 13% |
| R2 | Tirak Installation & Transfer to Temporary Drive | 35% |
| R3 | Full Rip-Out | 42% |
| | **TOTAL** | **100%** |

Logic: R3 (actual demolition/removal) carries the bulk of the weight since it's the largest scope. R2 (getting the tirak operational and the cabin transferred fully onto it) is technical and time-consuming despite touching nothing permanent. R0 mirrors Installation Stage 1 (Set Up) — same underlying logic, just for the rip-out phase.

**Universal across lift types.** These stages (R0–R3) apply to any rip-out — traction or hydraulic — with type-specific tasks living at the activity level inside each stage. No separate hydraulic/traction stage split; read the log and place it in the right stage.

### Stage R0 — Set Up (10% of rip-out total)
| Activity | % of stage |
|---|---|
| Toolbox/gear delivery for installer | 18% |
| Rip-out kit delivery (tools & gear specific to rip-out) | 18% |
| Hoardings & protection | 27% |
| Build working deck(s) — optional, job-specific | 7% |
| General preparation of building/site/compound | 20% |
| Other deliveries | 10% |

Notes:
- Confirmed addition (Danilo, Aug 2026): the rip-out phase was missing its own Set Up stage despite following the same logic as Installation Stage 1 — toolbox, hoardings, site prep, and deliveries all happen before R1 starts, and logs will show this activity distinctly from "Take Possession."
- **Glass shaft protection** (Danilo, Aug 2026): glass shafts need their own protective covering before rip-out begins — items dropped during demolition can crack/break the glass. Same logic and same activity as protecting the floor — falls under "Hoardings & protection" here, not a separate activity.
- **Smoke detector deactivation** (Danilo, Aug 2026): rip-outs happen in existing buildings, so there's almost always an active smoke detector nearby that needs to be deactivated before work starts. Standard part of rip-out Set Up — also under "Hoardings & protection" / general prep, same as smoke detector confirmation waits seen in real logs.
- **Hoardings vs. cages** (Danilo, Aug 2026): both fall under "Hoardings & protection" — hoardings are timber, cages are metal. Same activity, different material/construction depending on the job. A log saying "cages" (e.g. "ran all three cages" — 3 landing-level protective cages on this job, not 3 separate lifts) maps here just like a timber hoarding entry would.
- **Working deck(s)** are optional and job-specific — some jobs build one or more temporary working decks in the shaft for rip-out access, others don't. Left here as an optional line rather than assumed on every job.

| Activity | % of stage |
|---|---|
| Take possession of lift | 20% |

### Stage R2 — Tirak Installation & Transfer to Temporary Drive (35% of rip-out total)
| Activity | % of stage |
|---|---|
| Position cabin at correct height (before full kill) | 7% |
| Fully kill lift electrically / route mains power to tirak | 11% |
| Mount tirak | 9% |
| Setup electric chain block (secondary rigging tool, used alongside tirak) | 8% |
| Attach tirak to cabin | 9% |
| Hang tirak on hook point | 11% |
| Drive up with tirak, collect cabin on temporary motor | 14% |
| Release pressure from old ropes/belts (traction) OR detach piston (hydraulic) | 16% |
| Confirm free movement under tirak only, lift fully isolated/dead | 15% |

Notes:
- Confirmed sequence (Danilo, Aug 2026): if there's no existing beam/hook point, the old cabin — still alive — gets driven in inspection mode to access the top of the shaft so the beam can be installed (this is R1's beam task). Because mounting the tirak usually means routing mains power to it, which requires the lift to be dead, the cabin gets positioned at the right height *before* the final kill, then the lift is killed, then the tirak goes in around the now-stationary cabin.
- "Route mains power to tirak" typically means installing the Inex kit's orange box — the temporary 3-phase power box Schindler supplies for powering the tirak.
- Once the tirak is fully mounted and driving, the crew releases the old ropes/belts (traction) or detaches the piston (hydraulic), confirms the cabin moves freely under tirak power alone, and double-checks the lift is fully dead before rip-out begins.
- **R2 and former R3 (Transfer to Temporary Drive) merged (Danilo, Aug 2026)** — R3 was rarely evidenced as a distinct step in real logs; the tirak-mount and cabin-transfer work reads as one continuous activity in practice, so it's now one stage covering both.
- **Cabin weight can force a reeving-ratio change.** If the cabin is too heavy for the intended tirak ratio (e.g. 2:1), installers may strip components to lighten it before attaching ("make lift as light as possible"). If lightening still isn't enough, the ratio itself gets upgraded (e.g. 2:1 → 4:1) rather than proceeding underpowered. Log entries about lightening the cabin belong here, even though they can appear interleaved with R3-flavored entries (rip-out work starting before this stage fully completes is normal on real jobs).
- **Electric chain block** (Danilo, Aug 2026): a secondary rigging device, set up alongside the tirak — electric-powered, functions like a chain block. Used later in R3 for controlled lifting/lowering of components (car, CW tank) during rip-out. **Confirmed general-purpose, not Rip-Out-exclusive (Danilo, Sep 2026)** — also used during Installation (e.g., lifting the motor into place at the top of shaft).
- **Minifor** (Danilo, Sep 2026, corrected): a secondary rigging/lifting aid in its own right — mounted (e.g., to the ceiling) and used alongside the tirak, comparable in role to the electric chain block above. (Not, as an earlier draft had it, an alternate name for the winch/motor.)
- **"False car" system now has real Stage 1 activities (Danilo, Sep 2026)** — see Stage 1, "Install sky climber" / "Install sky lock." Some jobs use a false car (a temporary construction car distinct from our lift's cabin) raised by a sky climber instead of a tirak; the sky lock is that false car's speed governor equivalent. No longer treated as a flagged, un-weighted side-system.
- **Liftronic = Schindler** (Danilo, Aug 2026): Liftronic was acquired by Schindler — Liftronic-branded lifts are Schindler lifts, no functional difference. A log entry referencing Liftronic supplying/installing beam hardware isn't a different company's job by default; treat it as ordinary Schindler supply-chain activity on the same job unless there's other evidence it's genuinely a separate site.

### Stage R3 — Full Rip-Out (42% of rip-out total)
| Activity | % of stage |

# NON-PROGRESS LOG CATEGORIES
*(outside the 13-stage structure — 0% weight, does not count toward installation progress)*

These exist purely so freeform log entries have somewhere valid to land when they don't represent installation work. Without this bucket, the interpretation would either have to force-fit these into a real stage (corrupting the progress %) or drop them (losing part of the installer's logged day).

## Logistics & Site Support
- Material/tool handling (carrying up brooms, bolts, general gear)
- Deliveries (receiving, unloading, moving stock)
- Housekeeping (vacuuming, sweeping, general site tidiness)
- Site visits & client coordination (walkthroughs, check-measures, PM/client emails, general site checks not tied to a specific technical stage)
- Site induction (usually happens once, on first day at a new job)
- Daily pre-start (happens every day, doesn't represent build progress)

## Issues & Downtime
Lost/blocked time — no fault in work already done, just time that didn't go toward progress. Carries no weight, but useful for spotting recurring bottlenecks.
- Equipment/tool failures or issues (e.g. crane problems, faulty gear, RCD/power faults)
- Waiting on deliveries, access, or approvals (incl. wrong deliveries)
- Weather delays
- Other site downtime/blockers (e.g. no space to work, logistics constraints)

## Defects & Rework Flagged
Something already logged as installed/complete turns out to be wrong and needs fixing (e.g. brackets/bolts installed incorrectly, hazard found, component out of tolerance). Different from Issues & Downtime because it relates back to specific completed work, not just lost time.
- **v1 rule: flag only, don't auto-adjust progress.** The entry gets tagged against the relevant activity for review, but the % already credited stays as-is. Clawing back progress automatically would need a defensible reduction rule we don't have data for yet — revisit once we've seen more of these across real logs.

## Decisions log
- **Day-label text isn't authoritative — content is.** A log entry headed "rip out day N" (or "install day N") gets scored by what it actually describes, not by its label. Crews sometimes keep using the old day-counter for a day or two after crossing into the next phase (e.g. painting/prepping logged under a "rip out day 12" header). Read the content, place it in the right stage regardless of the header.
- **Floor-count scaling (Stages 6, 7, 11):** kept as fixed %, not tied to floor count, to keep v1 simple. Floor count is still captured as its own data point from the installer per project and can be factored in later if fixed weights prove inaccurate on very tall/short jobs.
- **Progress tracked per lift.** A multi-lift job (e.g. 3 lifts/stations at one site) runs a separate 0-100% Installation tracker (and separate Rip-Out tracker, if applicable) for each individual lift, not one pooled tracker for the whole job.
- **Multi-job days.** When an installer's log covers more than one job in a day (e.g. worked at Job A in the morning, Job B at night), the entry must be split before feeding it into either job's tracker — only the portion relevant to the job being tracked counts.
- **Helper/driver logs carry no independent weight.** Only the installer-of-record's log for a given day counts toward progress. Helper, apprentice, or driver entries for that same day are read for context/confirmation only — they don't add separately, since that would double-count the same day's actual progress.
- **Cross-job mislogs get excluded, not force-fit.** Occasionally an entry clearly references a different, unrelated job (e.g. naming another site or an already-completed job) with no plausible connection to the job being tracked. Confirmed (Danilo, Aug 2026): these get excluded entirely rather than mapped anywhere — someone logged it against the wrong job.
- **Installer handoffs mid-job are normal.** A departing installer will often leave a generic "items list"/pack-up entry for an incoming installer taking over the same job — this isn't a sign the job is finished, and logs can legitimately stop and later resume under a different installer's entries.
- **Informal staging locations are not fixed depots.** Confirmed (Danilo, Aug 2026): materials get shuffled between whichever job site has spare space at the time — an informal staging place name showing up as a materials source/destination on an unrelated job isn't automatically a wrong-job mislog on its own. Read each case on its content rather than treating the place name itself as a red flag.
- **The same real-world event can get logged more than once** (e.g. a task spanning 2 days, logged similarly on both, or logged separately by two different people). Treat as one continuous piece of work, not double-counted progress.
- **"Helped [name]" entries get credited if they name any specific task/component**, even minimal detail (e.g. "helped level the car," "helped with prep and inductions") — confirmed (Danilo, Sep 2026). Only entries with genuinely nothing beyond "helped [name]" stay unscored.
- **A log mentioning "brake" in the context of a work break** (e.g. "helped mark out on brake") can simply mean the installer received help while out on a break — not a mechanical brake component. Read plain-English breaks/rest-period phrasing before assuming a component name (Danilo, Sep 2026).
- **Batches without day-numbering** (no "Today day N" convention) — order can't be fully confirmed from content and time-of-day alone. Once this framework is running inside the actual software, per-day entries will make sequencing straightforward even without an explicit day counter; until then, treat any inferred ordering in a day-less batch as provisional.
- **Structure expanded from 13 to 14 stages** after comparing against a working 11-activity dashboard build. Added Stage 14 (Commissioning — covering Leveling & Adjustments, Testing, and Certification & Handover as sub-groups) to cover the phases after physical completion that get a lift actually signed off. Also folded in component gaps surfaced from real logs: guide shoes (car + CW), cabin ceiling, cabin sill, cabin header (mechanical), COP (mechanical), interior handrails/kickplates/bumpers, and plumb template removal. **All weights are temporary placeholders** — will be properly organized/calibrated together once the full Stage → Activity list is mapped out end to end.

# RECOMMENDED LOG ENTRY FORMAT (for installers)

Batch 1 showed that freeform logs are readable, but accuracy and consistency would improve a lot with a light structure — not a rigid form, just a habit. Goal: one line per distinct action, so each line maps cleanly to one Activity.

## The formula
**[VERB] + [QUANTITY, if applicable] + [ITEM/COMPONENT] + [LOCATION or DETAIL, if useful]**

Examples:
- "Installed 2 door blades — Lift 3"
- "Picked up delivery from Schindler office, dropped off at job site"
- "Wired 3-phase outlet for orange box — machine room"
- "Cleaned 4 car rails"
- "Surveyed shaft — Lift 1"

## Guidelines for installers
- **One line per action.** Don't bundle unrelated tasks into one sentence — split them.
- **Always name the lift/station** on multi-lift jobs (e.g. "Lift 3," "Station 2"). Without this, an entry can't be attributed to the right progress tracker.
- **Use a number whenever the task has one** — rails, doors, floors, bins, meters of scaffold, hours worked. Numbers are what let us gauge how *much* of an activity got done, not just that it was touched.
- **Use consistent verbs.** Suggested standard set:
  - Installed / Removed / Mounted / Attached — for physical component work
  - Wired / Connected / Tested — for electrical work
  - Delivered / Picked up / Dropped off / Unloaded — for logistics
  - Cleaned / Prepped / Painted — for prep work
  - Surveyed / Measured / Checked — for survey/verification work
  - Visited / Walked / Met with — for site visits and coordination
- **Note issues separately**, don't bury them in a progress line (e.g. "Crane issue on hire truck — delayed unloading 2 hrs" as its own line).
- **Include time worked** if shifts are irregular (e.g. "9pm-5am") — useful context even though it's not itself an activity.

## What this fixes from Batch 1
Several entries were hard to score precisely because they combined multiple actions in one sentence with no numbers (e.g. "Built doors, complete internal hoardings, creating door jambs..."). Under the formula, that becomes 3 separate lines, each individually attributable and (eventually) scoreable.

This doesn't need to be enforced rigidly — installers will still write naturally — but even loose adherence (numbers + one action per line + lift ID) will meaningfully improve interpretation accuracy.
